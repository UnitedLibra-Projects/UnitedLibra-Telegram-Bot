# Техническое задание

## 1. Общие сведения

**Название проекта:** Telegram-бот UnitedLibra  
**Назначение проекта:** предоставить пользователю Telegram-интерфейс для работы со справочниками и книгами библиотечной системы UnitedLibra.  
**Платформа клиента:** Telegram.  
**Язык реализации:** Python 3.11+.  
**Основные библиотеки:** `aiogram 3.x`, `aiohttp`, `pydantic-settings`.  

## 2. Цель разработки

Разработать Telegram-бота, который:

- выполняет регистрацию и вход пользователя;
- ограничивает доступ к функциям до авторизации;
- позволяет просматривать, добавлять и удалять записи;
- работает с каталогом библиотеки через HTTP API;
- хранит секретные параметры только во внешнем конфигурационном файле `.env`.

## 3. Объект автоматизации

Объектом автоматизации является процесс управления библиотечным каталогом через Telegram:

- авторы;
- категории;
- издатели;
- книги.

## 4. Функциональные требования

### 4.1. Требования к авторизации

Система должна:

- показывать стартовое меню по команде `/start`;
- предоставлять кнопки `Войти` и `Зарегистрироваться`;
- поддерживать локальную регистрацию по схеме `ФИО -> логин -> пароль`;
- поддерживать вход по схеме `логин -> пароль`;
- сохранять пользователей в локальном файле `users.json`;
- запрещать доступ к CRUD-функциям до успешного входа;
- поддерживать команду `/cancel` для отмены текущего действия;
- поддерживать выход из аккаунта через кнопку `Выйти`.

### 4.2. Требования к главному меню

После авторизации система должна:

- открывать главное меню;
- показывать разделы `Книги`, `Авторы`, `Категории`, `Издатели`;
- предоставлять переход к операциям с выбранной сущностью.

### 4.3. Требования к операциям CRUD

Для сущностей `Авторы`, `Категории`, `Издатели` система должна поддерживать:

- просмотр списка записей;
- добавление записи по полю `name`;
- удаление одной или нескольких записей по ID.

Для сущности `Книги` система должна поддерживать:

- просмотр списка книг;
- пошаговое добавление книги;
- удаление одной или нескольких книг по ID.

### 4.4. Требования к добавлению книги

При добавлении книги бот должен запрашивать:

- название книги;
- ISBN;
- год издания;
- ID издателя;
- ID авторов через запятую;
- ID категорий через запятую.

Система должна формировать JSON-запрос с полями:

- `title`;
- `isbn`;
- `year`;
- `publisher_id`;
- `author_ids`;
- `category_ids`.

### 4.5. Требования к интеграции с backend

Бот должен работать с сервисом каталога по HTTP и использовать следующие маршруты:

- `GET /books/get-authors`
- `POST /books/add-authors`
- `POST /books/delete-authors`
- `GET /books/get-categories`
- `POST /books/add-categories`
- `POST /books/delete-categories`
- `GET /books/get-publishers`
- `POST /books/add-publishers`
- `POST /books/delete-publishers`
- `GET /books/get-book`
- `POST /books/add-book`
- `POST /books/delete-book`

## 5. Нефункциональные требования

Система должна:

- работать асинхронно;
- не хранить токены и URL внутри исходного кода;
- использовать `.env` для конфигурации;
- скрывать `.env` и `users.json` через `.gitignore`;
- быть пригодной для запуска на локальной машине;
- поддерживать запуск в связке с PostgreSQL и backend каталога.

## 6. Требования к данным

### 6.1. Конфигурационные данные

В `.env` должны храниться:

- `BOT_TOKEN`
- `CATALOG_SERVICE_URL`
- `USERS_STORAGE_PATH`

### 6.2. Локальные данные

В файле `users.json` должны храниться:

- ФИО пользователя;
- логин;
- соль пароля;
- хеш пароля.

### 6.3. Данные каталога

В PostgreSQL должны использоваться таблицы:

- `authors`
- `categories`
- `publisher`
- `books`
- `bookauthors`
- `bookcategories`
- `bookcopy`
- `bookcopypublishers`
- `locations`
- `users`

## 7. Требования к интерфейсу

Интерфейс должен быть текстовым и кнопочным, внутри Telegram.

Система должна использовать:

- reply-клавиатуру для стартового и главного меню;
- inline-клавиатуру для операций просмотра, добавления и удаления.

## 8. Требования к структуре проекта

Проект должен содержать:

- `bot.py` — точка входа;
- `config.py` — загрузка настроек;
- `auth_storage.py` — локальное хранилище пользователей;
- `handlers_auth.py` — регистрация и вход;
- `handlers_crud.py` — работа с каталогом;
- `requirements.txt` — зависимости;
- `.env.example` — шаблон конфигурации;
- `.gitignore` — исключения для Git;
- `start_bot.ps1` — запуск бота;
- документацию в папке `docs`.

## 9. Критерии приемки

Работа считается выполненной, если:

- бот запускается без ошибок;
- пользователь может зарегистрироваться и войти;
- без входа CRUD-функции недоступны;
- списки авторов, категорий, издателей и книг открываются;
- можно добавить запись;
- можно удалить запись;
- конфигурация вынесена в `.env`;
- документация содержит ТЗ, блок-схемы, UML-диаграмму и ER-диаграмму.

## 10. Результат разработки

Результатом разработки является готовый к демонстрации Telegram-бот UnitedLibra с документацией, Git-репозиторием и рабочей интеграцией с backend каталога.
